# imgTool

Настольное приложение для Windows на WPF (.NET 9) для пакетной обработки изображений: изменение размера, обрезка, поворот, конвертация, удаление хромакея, водяные знаки, сборка коллажей и работа с метаданными.

Интерфейс полностью на русском языке, оформлен в тёмной теме.

## Возможности

### Пакетная обработка

- Добавление файлов и папок, в том числе с подпапками, и перетаскивание (drag & drop).
- Изменение размера:
  - «Вписать в рамки» (Fit) — изображение целиком помещается в заданные ширину и высоту;
  - «Заполнить с обрезкой» (Cover) — заполняет рамку с центральной или якорной обрезкой;
  - «Растянуть» (Stretch) — точные ширина и высота без сохранения пропорций;
  - «Процент» — масштабирование на заданный процент.
- Опция «Не увеличивать изображения».
- Обрезка под заданную пропорцию с привязкой к девяти точкам.
- Массовая обрезка кадров:
  - по пропорции;
  - одинаковыми полями со всех сторон;
  - фиксированным прямоугольником с координатами от левого верхнего угла.
  Поля и прямоугольник задаются в пикселях или процентах от размера каждого изображения.
- Удаление хромакея:
  - ключевой цвет в HEX, допуск и смягчение границ;
  - подавление цветного ореола на краях объекта;
  - выбор цвета подложки для JPEG и BMP.
- Поворот на 90°, 180°, 270° и отражение по горизонтали/вертикали.
- Водяной знак:
  - текст: шрифт, размер, цвет (HEX), прозрачность, позиция, отступ, тень;
  - логотип: PNG/JPG/BMP/WebP, ширина в процентах от изображения, прозрачность, позиция, отступ.
- Конвертация между JPEG, PNG, WebP и BMP; качество для JPEG/WebP.
- Шаблон имени результата с подстановками:
  `{name}`, `{ext}`, `{format}`, `{index}`, `{date}`, `{width}`, `{height}`.
- Выбор папки результата (по умолчанию — рядом с исходником).
- Политика при совпадении имён: добавить суффикс `(2)`, перезаписать или пропустить.
- Предпросмотр выбранного файла, журнал обработки, отмена операции.
- Сохранение метаданных для цепочки JPEG → JPEG (best effort).

### Коллаж

- Сетка с настраиваемым числом колонок и шириной результата.
- Ширина может быть не задана: тогда ширина ячейки берётся из первого изображения, а итоговая ширина рассчитывается по числу колонок.
- Режимы склейки:
  - **вертикальная** — кадры в один столбец без масштабирования, ширина по самому широкому кадру;
  - **горизонтальная** — кадры в одну строку без масштабирования, высота по самому высокому кадру.
- В режиме склейки изображения сохраняют исходный размер, выравниваются по центру поперечной оси, а свободное место заполняется фоном.
- Пропорция ячейки, отступы между изображениями и поля вокруг.
- Режимы заполнения ячейки: «Заполнить с обрезкой» или «Вписать целиком».
- Цвет фона в формате HEX (#RGB, #RRGGBB или #AARRGGBB).
- Прозрачный фон для PNG и WebP — отдельным переключателем или через альфа-канал в HEX.
- Изменение порядка изображений, предпросмотр готового коллажа.
- Сохранение в JPEG, PNG, WebP или BMP с настройкой качества.

### Метаданные

- Сводка по файлу: размеры (с учётом EXIF-ориентации), формат, вес, дата съёмки, наличие метаданных.
- Просмотр EXIF и GPS с русскими подписями основных полей.
- Удаление метаданных перекодированием изображения.
- Переименование по дате съёмки (или дате файла, если EXIF отсутствует) с шаблоном:
  `{date}`, `{time}`, `{name}`, `{ext}`.

### Настройки

- При закрытии сохраняются параметры пакетной обработки, коллажа и раздела метаданных.
- Запоминаются последний открытый раздел, положение, размер и развёрнутое состояние окна.
- Списки файлов, журнал обработки и предпросмотр между запусками не сохраняются.
- Файл настроек: `%APPDATA%\imgTool\settings.json`.

## Поддерживаемые форматы

| Формат | Чтение | Запись | Примечание |
|--------|:------:|:------:|------------|
| JPEG (.jpg, .jpeg) | да | да | без прозрачности, качество 1–100 |
| PNG | да | да | прозрачность сохраняется |
| BMP | да | да | запись 24 бита, без альфа-канала |
| WebP | да | да | статичный WebP, качество 1–100 |

GIF, TIFF, TGA, PBM и другие форматы не поддерживаются.

### Ограничения

- **Прозрачность.** JPEG и BMP не поддерживают альфа-канал: при сохранении прозрачные области накладываются на белый фон (для хромакея можно выбрать свой цвет подложки). PNG и WebP прозрачность сохраняют. В коллаже прозрачный фон можно включить переключателем или задать цветом с альфа-каналом, например `#0012161F`.
- **Метаданные.** Переносятся только при сохранении JPEG поверх JPEG. Копируются APP-сегменты EXIF, XMP, ICC и IPTC; поле `Orientation` при этом сбрасывается в `1`, так как поворот уже применён к пикселям. Для остальных форматов и направлений конвертации метаданные не сохраняются.
- **EXIF-ориентация.** При чтении поворот из EXIF применяется автоматически, поэтому размеры в интерфейсе и результат соответствуют видимому изображению.
- **Удаление метаданных.** Выполняется перекодированием. Для JPEG это повторное сжатие с качеством 92, то есть небольшая потеря качества. Операция необратима.
- **Анимированные WebP.** Обрабатывается только первый кадр.
- **Размер коллажа.** Итоговое изображение ограничено 20 000 px по каждой стороне. Для длинных склеек уменьшите число кадров или отступы.
- **Массовая обрезка.** При обрезке полями или прямоугольником в пикселях область должна помещаться в каждый кадр. Если кадр меньше заданной области, он попадёт в журнал как ошибка; для разноразмерных изображений используйте проценты.
- **Хромакей.** Удаляет пиксели, близкие к ключевому цвету по цветности Cb/Cr. Это не AI-сегментация: сложные фоны, волосы и полупрозрачные объекты могут требовать подбора допуска и смягчения. Прозрачность сохраняется в PNG и WebP; JPEG и BMP сохраняются на выбранном фоне.
- **Переименование.** Если целевое имя занято, добавляется суффикс `(2)`, `(3)` и т. д.
- **Совпадение путей.** Если выбрать папку результата, совпадающую с папкой исходников, а шаблон имени — без суффикса, политика «Перезаписать» может заменить исходный файл. По умолчанию используется шаблон `{name}_out`, поэтому этого не происходит.

## Стек

- .NET 9, WPF, MVVM без сторонних UI-фреймворков.
- [SkiaSharp](https://github.com/mono/SkiaSharp) 3.119.4 — декодирование, преобразования и кодирование изображений.
- [MetadataExtractor](https://github.com/drewnoakes/metadata-extractor-dotnet) 2.9.3 — чтение EXIF/GPS.
- xUnit — тесты ядра и приложения.
- ImageSharp не используется.

## Структура решения

```
ImgTool.sln
src/
  ImgTool.Core/            — обработка изображений, метаданные, коллажи
    Models/                — параметры и результаты операций
    Services/              — SkiaImage, ImageProcessor, CollageBuilder,
                             MetadataService, JpegMetadataPreserver и др.
  ImgTool.App/             — WPF-приложение
    Infrastructure/        — MVVM-база, команды, загрузка превью
    Models/                — FileItem, NamedValue
    Settings/              — сохранение и восстановление настроек
    ViewModels/            — Main, Batch, Collage, Metadata
    Views/                 — BatchView, CollageView, MetadataView
tests/
  ImgTool.Core.Tests/      — тесты обработки изображений (xUnit)
  ImgTool.App.Tests/       — тесты сохранения настроек (xUnit)
```

## Сборка и запуск

Требования: Windows 10/11 и [.NET 9 SDK](https://dotnet.microsoft.com/download).

```powershell
dotnet restore ImgTool.sln
dotnet build ImgTool.sln -c Release
dotnet run --project src/ImgTool.App/ImgTool.App.csproj -c Release
```

Готовый исполняемый файл:

```
src/ImgTool.App/bin/Release/net9.0-windows/ImgTool.App.exe
```

Публикация самодостаточной сборки:

```powershell
dotnet publish src/ImgTool.App/ImgTool.App.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true
```

## Тесты

```powershell
dotnet test ImgTool.sln -c Release
```

Тесты покрывают загрузку и EXIF-ориентацию, изменение размера, обрезку, поворот и отражение, сохранение во все поддерживаемые форматы, водяные знаки, коллажи, шаблоны имён, работу с метаданными, переименование и сохранение настроек.

## Диагностика

Необработанные исключения при запуске и во время работы записываются в файл:

```
%TEMP%\imgtool-startup.log
```

Если приложение не запускается, проверьте этот файл и наличие .NET 9 Desktop Runtime.

Ошибки чтения или записи настроек записываются отдельно:

```
%TEMP%\imgtool-settings.log
```

При повреждённом файле настроек приложение запускается со значениями по умолчанию, а при следующем закрытии перезаписывает его корректным файлом.
